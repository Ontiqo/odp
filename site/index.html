Open Display Protocol

Show a computer on any screen on the network.

ODP is an open protocol for showing a computer’s screen, sound and films on other screens on the same network: TVs, Raspberry Pis, old PCs and tablets. The keyboard, mouse and touch of those screens go back to the computer, and anyone may build a receiver or a host from it.

The specification

One document, eight layers.

A receiver can be written on any platform from SPEC.md alone. Version 1.0 changes only by errata. New features come as 1.x minor versions, which add only optional messages and fields: both sides send the versions they speak in hello and use the highest they share.

Layers

L0
Discovery DNS-SD over mDNS, _odp-receiver._tcp
L1
Control framed JSON over TCP, ports 54330–54332 when free
L2
Pairing and keys a 6-digit PIN or a QR code, then per-session keys
L3
Session capabilities, mirror or extend, layout
L4
Media H.264 (HEVC and AV1 optional), Opus or PCM, over UDP
L5
Clock and sync a shared clock, latency reports, calibration
L6
Input keyboard, pointer, touch, pen and game controllers back to the host
L7
Cinema a film played by each screen’s own player, in step

Versions

  1. 1.528 Nov 2026

    Combining: a screen says how many pictures it plays at once (caps.streams) and who is showing on it (screen.showing), so the computers showing can agree on one of them combining the pictures into one stream.

  2. 1.428 Nov 2026

    Connect-out: screens whose apps can only dial out (LG webOS, Hisense VIDAA) reach a host over WebSockets.

  3. 1.328 Nov 2026

    monitor.switched: the answer to a switch, or why not in plain words. A discovery hint for how a screen brings up its PIN.

  4. 1.227 Nov 2026

    Monitor inputs: a screen on one input of a monitor switches the monitor to its other inputs (monitor.inputs, monitor.switch).

  5. 1.127 Nov 2026

    Game controllers, and rooms: the computers that own a screen see who is showing and can end a presentation (room.*).

  6. 1.027 Nov 2026

    Frozen: discovery, pairing, encrypted sessions, video and sound on a shared clock, input and Cinema. The same on the wire as the 0.1 draft.

Build a receiver or a host

Start from the reference code.

Everything is Rust, in one repository. The odp crate does identities, PIN pairing, encrypted sessions, the shared clock and media packets. It has no capture, codecs or windows of its own: a receiver adds its platform’s decoder and display, a host its capture and encoder.

receiver/

The reference receiver

Listens on 54330–54332 (any free port when those are taken), pairs with the PIN it shows, runs a session, keeps the shared clock and hands over each frame with the moment to show it. It sends the screen’s keys and pointer back. A screen app adds only its decoder and window.

Rust apps use it directly, others through its C interface (ffi), and Android through its Java interface (feature android).

web/

The web receiver

The receiver as WebAssembly, for TV platforms whose apps can’t use UDP, such as LG webOS and Samsung Tizen. It talks to the host over one WebSocket (the web profile); pairing and encryption stay end to end, and frames decode with WebCodecs.

out/

Connect-out for hosts

odp-out listens for screens that can only dial out. Each one appears to the host as an ordinary screen on a loopback address, so nothing else in the host changes.

conformance/

odp-check

A conformance host. It pairs (after trying a wrong PIN), comes back as a paired host, casts H.264 colour bars, loses a frame, replays a packet, answers clock pings, asks for Cinema, watches the room and sends the monitor’s inputs. Then it prints each check, the version both sides speak and the levels the receiver meets.

Test your receiver

Show a PIN on the receiver, then run odp-check with its address and port. --key waits that many seconds for a key pressed at the receiver; --switch for “ODP check input” chosen in its menu. For a screen that connects out, --out <pin> --lan waits for it to dial in.

  • Basic discovery to media, with H.264 and clock pings
  • Synced latency reports and calibration
  • Interactive input back to the host
  • Cinema films in step
  • Rooms answers an owner’s room.watch (1.1)
  • Inputs monitor inputs and switching (1.2, 1.3)
